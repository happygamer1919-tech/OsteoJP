## Standing rules (owner, amended 2026-07-24 — NON-NEGOTIABLE)

1. **Migrations are apply-BEFORE-merge.** CYAN clear → owner runs a TERMINAL apply
   with pasted JOURNAL evidence → THEN merge. Merging a migration before the prod
   apply breaks the deploy (the twin 0044/0045 outages above).
2. **"Applied" = pasted journal output only.** The word "applied" from anyone
   (including GREEN) requires the pasted journal/count-delta + nullability flip —
   NEVER inferred from absence of runtime errors. (Note: drizzle
   `__drizzle_migrations.created_at` is journal-GENERATION time, not apply
   wall-clock — prove applies by the count delta, never that timestamp.)
3. **Auto-merge DISABLED repo-wide.** Owner merge instructions execute ONLY at the
   moment given, never armed for later. Non-migration loops self-merge on green
   CI; migrations build + HALT for owner apply-before-merge.
4. **Owner-terminal prod writes.** GREEN NEVER sources prod credentials. The owner
   runs every prod write / apply / seed in his own terminal; GREEN STAGES the
   byte-exact script + VERIFIES from pasted evidence. Destructive ops are
   owner-confirmable — log and block, never execute autonomously.
5. **One-time admin-merge exception (2026-07-27):** #664 was admin-merged with
