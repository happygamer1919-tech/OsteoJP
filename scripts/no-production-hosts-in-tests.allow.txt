# scripts/no-production-hosts-in-tests.test.mjs; its header says what a hit is.
#
# One entry per line, three fields separated by a TAB:
#
#   <path>	<sha256 of the line, trimmed>	<why this line cannot reach production>
#
# The failing check prints the first two fields for every new hit. An entry is
# added only after a person has read the line and found that nothing on it can
# open a connection to production, and only in a pull request titled
# GATE-CHANGE that the owner merges by hand: this file is pinned in
# .github/gate-manifest.json because an entry here silences the check.
#
# An entry clears every identical trimmed line in its file. Any edit to the line
# changes the hash and the line comes back as a hit. An entry that clears no line
# fails the check as STALE. An entry on a line that defines a constant also
# allows every later use of that constant in the file, because only the line
# that spells the name is read: read every use before adding one. An entry
# whose reason starts FOLLOW-UP is allowed today but names a test that should
# be changed, and is listed on the card.
#
# The preferred fix for a new hit is not an entry here: it is a reserved name,
# such as portal.<the production domain>.invalid, which never resolves.
